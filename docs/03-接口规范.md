## 全局接口规范

- **基础 URL**：开发环境默认为 `http://localhost:3000/api`。
- **数据格式**：统一使用 JSON。
- **版本管理**：暂不使用 URL 版本号，后续如有需要可演进为 `/api/v1/*`。

## 认证与授权

- 认证方式：使用 Bearer Token（JWT）进行认证。
- 认证头部示例：

```http
Authorization: Bearer <access_token>
```

## 健康检查接口（已实现）

- `GET /api/health`
  - **说明**：用于检查后端服务是否可用。
  - **请求参数**：无
  - **响应示例**：

```json
{
  "status": "ok",
  "timestamp": "2026-03-10T00:00:00.000Z"
}
```

## Auth 模块接口（初版）

### 注册

- `POST /api/auth/register`
  - **说明**：创建新用户账号并返回访问令牌与刷新令牌。
  - **请求体示例**：

```json
{
  "email": "user@example.com",
  "password": "secret123",
  "name": "Alice"
}
```

  - **响应示例**：

```json
{
  "user": {
    "id": "ckxyz...",
    "email": "user@example.com",
    "name": "Alice"
  },
  "accessToken": "<access_token>",
  "refreshToken": "<refresh_token>"
}
```

### 登录

- `POST /api/auth/login`
  - **说明**：使用邮箱与密码登录，返回访问令牌与刷新令牌。
  - **请求体示例**：

```json
{
  "email": "user@example.com",
  "password": "secret123"
}
```

  - **响应示例**：同注册接口。

## Workspace 模块接口（初版）

> 所有 Workspace 接口均需要携带 Bearer Token（通过登录接口获取）。

### 创建 Workspace

- `POST /api/workspaces`
  - **认证**：需要 `Authorization: Bearer <access_token>`
  - **请求体示例**：

```json
{
  "name": "Demo Workspace",
  "description": "用于测试的空间"
}
```

  - **响应示例**：

```json
{
  "workspace": {
    "id": "ck...",
    "name": "Demo Workspace",
    "description": "用于测试的空间",
    "ownerId": "ck-user...",
    "createdAt": "2026-03-10T00:00:00.000Z",
    "updatedAt": "2026-03-10T00:00:00.000Z"
  }
}
```

### 获取当前用户的 Workspace 列表

- `GET /api/workspaces`
  - **认证**：需要 `Authorization: Bearer <access_token>`
  - **响应示例**：

```json
{
  "workspaces": [
    {
      "id": "ck...",
      "name": "Demo Workspace",
      "description": "用于测试的空间",
      "ownerId": "ck-user...",
      "createdAt": "2026-03-10T00:00:00.000Z",
      "updatedAt": "2026-03-10T00:00:00.000Z"
    }
  ]
}
```
